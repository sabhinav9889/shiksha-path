# Git hooks are off in a fresh worktree until `npm ci`

**What breaks:** in a new `git worktree` (or a fresh clone), commits to `main`, bad commit messages
and unscanned secrets all go through: no hook runs.

**Why:** Husky sets `core.hooksPath=.husky/_`, a relative path shared by every worktree. `.husky/_`
is generated by `npm install`/`npm ci` and git-ignored, so it doesn't exist in a new worktree until
you install there.

**How to avoid:** run `npm ci` in every new clone or worktree before working. The Claude Code edit
hook (`.claude/hooks/block-main-edit.sh`) refuses edits in a checkout that tracks `.husky/` but has
no `.husky/_`, with that instruction. CI still re-checks everything on the PR.
